# Отчет по этапу ETL и Feature Engineering: Подготовка данных антифрода

## Цель этапа
Создание стабильной, масштабируемой и защищенной от утечек во времени (Data Leakage) витрины признаков на основе сырых логов транзакций (`final_trans_log.csv`) и целевых P2P-переводов (`final_p2p_log.csv`).

---

## Архитектура Feature Engineering (Ноутбук 1)

Предыдущие кумулятивные метрики вызывали сильный временной дрейф признаков (Data Drift) на отложенном тесте. В итоговом решении вся архитектура переведена на **динамические сессионные и порядковые маркеры**:

### 1. Порядковые сессионные признаки покупок (транзакций)
* **Порядковый номер (`trans_rank`):** Накопительный номер покупки строго внутри сессии пользователя. *Примечание:* данный признак вычисляется в ноутбуке, но **намеренно исключён** из итогового набора фичей для предотвращения кумулятивного временного дрейфа на тесте.
* **Микротайминг транзакций (`time_diff_trans`):** Время в секундах между текущей и предыдущей покупкой клиента. Блокирует автоматические скрипты списаний.
* **Локальный шок суммы (`trans_amt_to_mean_3`):** Отношение текущей суммы покупки к скользящему среднему трех предыдущих транзакций клиента. Выявляет резкие нетипичные всплески трат.
* **Категориальный профиль интересов (`prop_`)**: Скользящие доли категорий магазинов (`MerchantType`) в последних 5 покупках клиента с лагом в 1 шаг для предотвращения заглядывания в будущее.

### 2. Порядковый профиль P2P-переводов
* **Интервал между переводами (`time_diff_p2p`):** Дистанция в секундах между последовательными переводами. Фродеры обычно выводят деньги быстрыми транзакциями подряд.
* **Относительный шок перевода (`p2p_amt_to_mean_3`):** Отношение суммы текущего перевода к среднему объёму трех предыдущих P2P-операций пользователя.

## Хронологическое склеивание (As-Of Merge)

Для исключения утечки данных из будущего при обогащении P2P-перевода историей обычных трат применен строго направленный назад поиск:

```python
df_final = pd.merge_asof(
    left=df_p2p, 
    right=trans_features, 
    on='EventTime', 
    by='UserID', 
    direction='backward',
    tolerance=pd.Timedelta('7d')
)
```

### Ключевые механизмы защиты данных:
1. **`direction='backward'`**: Подтягивает профиль трат, сформированный *строго до* секунды совершения перевода.
2. **`tolerance=pd.Timedelta('7d')`**: Если клиент не совершал обычных покупок более 7 дней, его профиль трат признается неактуальным (заменяется на `-1`). Это защищает модель от использования устаревших данных.
3. **Обработка холодного старта (`is_cold_user`)**: Бинарный маркер отсутствия истории покупок. Позволяет модели моментально детектировать операции по "прогретым" только под вывод картам.
4. **Усечение выбросов (Clipping)**: Числовые признаки (`Amount`, интервалы времени и отношения) жестко обрезаны по $99$-му перцентилю. Это предотвращает появление бесконечностей при делении на малые величины и стабилизирует сплиты деревьев решений.
