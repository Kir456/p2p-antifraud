# Отчет по этапу ML-моделирования: Антифрод P2P-переводов

## Цель этапа
Разработка и оптимизация модели машинного обучения для выявления мошеннических P2P-транзакций. 
* **Бизнес-требование:** Обеспечение покрытия (Recall) $\ge$ 70%.
* **Ограничение данных:** Использование только трех базовых признаков (`amount`, `hour`, `day_of_week`).
* **Специфика выборки:** Экстремальный дисбаланс классов (~0.08% фрода).

---

## Методология и Архитектура

Для обеспечения надежности модели и предотвращения утечки данных (Data Leakage) был выстроен следующий конвейер:

1. **Валидация:** Подход **Out-of-Time (OOT) Holdout**. Строгое хронологическое разделение на Train (80%) и Test (20%).
2. **Кросс-валидация:** Подбор гиперпараметров через `TimeSeriesSplit` на обучающей выборке.
3. **Основной алгоритм:** **CatBoost**. Оптимизация метрики `average_precision` (PR-AUC) и использование внутренней обработки категориальных признаков.
4. **Архитектурное решение:** Внедрена **Двухстадийная фильтрация (Каскад)** для обработки транзакций с неуверенными предсказаниями («серая зона»).

---

## Результаты тестирования

### 1. Базовая модель (CatBoost + GridSearchCV)
Модель отлично выявляет очевидные мошеннические паттерны, однако для достижения целевого Recall порог уверенности был снижен, что привело к падению Precision.

* **ROC-AUC:** 0.8126
* **PR-AUC:** 0.4531
* **Бизнес-метрики (Порог 0.1538):**
  * Recall: 0.7002
  * Precision: 0.0033

### 2. Двухстадийная фильтрация (Каскадный ансамбль)
* **Стадия 1:** Отсечение очевидного фрода и безопасных транзакций.
* **Стадия 2:** Микро-модель, обученная исключительно на «серой зоне» (вероятности от 0.05 до 0.80 первой модели).

**Статистика выборки каскада:**
* Общий размер обучающей выборки: 2,755,091 строк
* Размер «серой зоны»: 1,388,053 строк (~50% трафика)

**Итоговые метрики каскада на отложенном тесте:**

| Метрика | Значение | Изменение |
| :--- | :--- | :--- |
| **ROC-AUC** | 0.8216 | `+ 0.009` |
| **PR-AUC** | 0.2127 | *-* |
| **Оптимальный порог** | 0.3002 | *-* |
| **Recall** (Цель) | 0.7002 | *Зафиксировано* |
| **Precision** | 0.0040 | **+ 21.2% (относительно базы)** |

> **Итог:** Каскадный подход повысил итоговую точность (Precision) на 21% при сохранении необходимого Recall. Это алгоритмический максимум для текущего набора признаков.

---

## Основные выводы и Инсайты

1. **Алгоритмический предел достигнут.** Альтернативные алгоритмы (Logistic Regression, LightGBM) и методы кодирования (Target Encoding, OHE) показали результаты на уровне случайного угадывания (PR-AUC < 0.001). Внутренние механизмы CatBoost оказались наиболее эффективными.
2. **Дефицит информационной емкости.** Около 50% транзакций (1.3 млн) попали в «серую зону». В координатах только суммы и времени честные пользователи и мошенники ведут себя идентично. Без дополнительного контекста разделить эти классы математически невозможно.

**Задачи для Data Engineer:**
Добавить в матрицу `X` следующие агрегаты:
* **Частотные (Velocity/Frequency):** Время с прошлого перевода, количество переводов за 1 и 24 часа для конкретного `UserID`.
* **Аномалии (Z-Score):** Отношение суммы текущего перевода к среднему чеку `UserID` за прошлый месяц.
* **Сетевые связи:** Флаг новизны получателя (первый ли это перевод данному адресату).

*После добавления этих признаков текущая архитектура каскада позволит кратно увеличить Precision.*
